
## 3. 开场讲解稿

可以照着说：

> 老师好，我这个项目叫“智学扫描”，主题是基于 ML Kit 与 SQLite 的校园学习资料识别与错题管理 App。它解决的是学生平时拍了很多教材、试卷、PPT 截图以后难以检索、难以整理错题的问题。
>
> 项目不是简单保存图片，而是把图片通过 OCR 转成文本，再把标题、内容、科目、标签、来源类型、原图 Uri、是否错题、错误原因、复习次数和掌握状态结构化保存到本地 SQLite 中。这样用户后续可以在知识库里搜索资料，也可以在错题复习中心集中复习错题。
>
> 技术上使用 Java + XML，页面结构是 Activity + Fragment，列表用 RecyclerView，本地数据库用 SQLiteOpenHelper，设置项用 SharedPreferences，OCR 使用 Google ML Kit，并且针对中文教材加入了中文 OCR 模型。OCR 结果保留可编辑能力，用来处理数学公式和版式识别不完全准确的问题。

## 5. 技术架构讲解

### 5.1 整体架构

可以这样讲：

> 项目采用比较标准的 Android 课程项目结构。页面层使用 Activity + Fragment，列表使用 RecyclerView，数据层使用 SQLiteOpenHelper 和 Repository，设置项使用 SharedPreferences，OCR 能力封装在 OcrManager 中，提醒相关能力预留在 worker 和 receiver 包中。

包结构说明：

```text
com.example.smartscan
├── ui
│   ├── activity      页面入口和复杂页面
│   ├── fragment      底部导航中的模块页面
│   ├── adapter       RecyclerView 适配器
├── data
│   ├── entity        实体类
│   ├── db            SQLiteOpenHelper
│   └── repository    数据访问封装
├── ocr               ML Kit OCR 封装
├── worker            复习提醒预留
├── receiver          开机恢复提醒预留
└── util              工具类
```

### 5.2 数据库设计

核心表：

```text
StudyMaterial
```

主要字段：

```text
id
title
content
subject
sourceType
tags
imagePath
isWrongQuestion
difficulty
note
wrongReason
mastered
nextReviewTime
createTime
updateTime
reviewCount
lastReviewTime
```

讲解重点：

> 所有资料都存在 StudyMaterial 表中。错题不是另一张表，而是通过 isWrongQuestion 字段标记。这样普通资料和错题资料可以保持统一，不会出现两份数据不一致的问题。

### 5.3 Repository 层

可以这样讲：

> 我没有把 SQL 全部写在 Activity 里，而是用 StudyMaterialRepository 封装了 insert、update、delete、search、getWrongMaterials、reviewOnce、markMastered 等方法。这样页面只负责展示和交互，数据访问集中管理，代码结构更清楚。

### 5.4 OCR 设计

OCR 流程：

```text
选择图片 Uri
↓
解码 Bitmap
↓
选择中文 OCR 或通用 OCR
↓
ML Kit 识别
↓
结果填入文本框
↓
用户可编辑修正
```

讲解重点：

> ML Kit 的通用 OCR 对中文教材和数学公式不是完全理想，所以我增加了中文 OCR 模型，并保留 OCR 结果可编辑能力。这样即使公式、矩阵或手写批注识别不完整，用户也可以现场修正后再保存。

## 6. 项目创新点讲解

### 6.1 OCR + 本地知识库

不是简单图片保存，而是将图片内容转成可检索文本，并结构化存入 SQLite。

答辩表述：

> 传统方式中，学生拍了很多图片后只能在相册里翻找，图片中的文字不能搜索。本项目通过 OCR 把图片内容变成文本，并按科目、标签、来源类型保存，形成本地知识库。

### 6.2 中文 OCR 与可编辑结果

答辩表述：

> 针对中文教材场景，我接入了 ML Kit 中文识别模型。考虑到数学公式和复杂版式识别可能不完全准确，项目没有把 OCR 结果当作最终答案，而是允许用户继续编辑后保存。

### 6.3 知识库与错题中心分层

答辩表述：

> 知识库用于管理全部资料，错题中心只展示被标记为错题的资料。两者不是重复页面，而是同一张表的不同业务视角。

### 6.4 错题复习过程管理

答辩表述：

> 错题中心不仅能收藏错题，还能记录错误原因、难度、复习次数、上次复习时间和掌握状态，更接近真实复习流程。

### 6.5 原图追溯

答辩表述：

> OCR 文本可能需要核对，所以详情页保留原图预览。用户可以对照原图修正 OCR 内容。

## 7. 高频答辩问题与标准回答

### Q1：项目完成了哪些课程考察点？

答：

> 项目覆盖了 Activity、Fragment、RecyclerView、SQLiteOpenHelper、SharedPreferences、第三方依赖 ML Kit、Material Design UI、本地数据持久化、BroadcastReceiver 和 Worker 预留等课程知识点。其中 CRUD、页面跳转、列表展示、本地数据库和设置保存都已经完整实现。

### Q2：核心 CRUD 是否完整？

答：

> 完整。Create 是扫描页新增资料；Read 是首页、知识库、错题中心和详情页查询资料；Update 是详情页编辑、错题中心复习一次和标记已掌握；Delete 是详情页删除资料。所有操作都通过 Repository 访问 SQLite。

### Q3：为什么使用 SQLiteOpenHelper，而不是 Room？

答：

> 因为这是移动应用开发课程作业，SQLiteOpenHelper 更能直接体现数据库创建、升级和 SQL 增删改查过程。为了避免代码混乱，我用 Repository 封装数据库操作。后续如果项目工程化程度更高，可以迁移到 Room。

### Q4：知识库和错题本是不是重复？

答：

> 不是。知识库是全部资料总仓库，错题本是基于 StudyMaterial 表中 `isWrongQuestion = 1` 筛选出来的复习视图。错题本没有维护另一套重复数据。

### Q5：为什么 OCR 数学公式不够准确？

答：

> 当前使用的是 Google ML Kit Text Recognition，它适合普通文本、中文题干、英文和数字识别，但复杂数学公式、矩阵、上下标和手写批注不是它的强项。所以项目保留了 OCR 文本可编辑能力，允许用户修正。后续可以接入 Mathpix、PaddleOCR 或大模型视觉识别增强公式识别。

### Q6：为什么没有继续保留框选 OCR？

答：

> 区域框选确实是一个有价值的后续方向，但在模拟器和 Mac 触摸板环境下，拖拽手势不够稳定，容易影响现场验收。当前版本优先保证核心闭环稳定：选图、整图 OCR、文本编辑、SQLite 保存、知识库检索和错题复习。后续如果接入真机手势或拍照裁剪，可以再扩展区域 OCR。

### Q7：图片保存在哪里？

答：

> 图片本身仍在系统相册或文件系统中，App 保存的是系统返回的 Uri 字符串到 `imagePath` 字段。详情页通过 Uri 加载原图。这样避免复制大图片，也能追溯原始资料。

### Q8：如果图片 Uri 失效怎么办？

答：

> 详情页做了异常处理，如果 Uri 为空或读取失败，会显示“暂无原图”或“原图无法读取”，不会影响 OCR 文本和其他资料字段查看。

### Q9：为什么没有做 CameraX？

答：

> 当前 V1.1 阶段需求是相册选择、真实 OCR 和原图管理。CameraX 拍照属于后续扩展，我在项目结构中预留了方向，但没有提前实现，避免扩大范围影响稳定性。

### Q10：复习提醒是否真正可用？

答：

> 当前设置页已经能保存提醒开关和提醒时间，Worker、Scheduler、BootReceiver 也已经预留。真实定时通知属于 V1.2，可以基于 WorkManager 或 AlarmManager 继续实现。

### Q11：数据重启后会丢吗？

答：

> 不会。学习资料保存在 SQLite 数据库中，设置保存在 SharedPreferences 中。只要不卸载 App 或清空应用数据，重启后数据仍然存在。

### Q12：数据库升级怎么处理？

答：

> DBHelper 中维护数据库版本号，并在 `onUpgrade()` 中通过 `ALTER TABLE` 增量添加新字段，例如 wrongReason、mastered、nextReviewTime，避免老数据库升级时崩溃或直接丢数据。

### Q13：项目是否上传用户图片或学习内容？

答：

> 不上传。当前实现以本地处理和本地存储为主，OCR 文本、图片 Uri 和设置项都保存在本机，更符合学习资料隐私保护需求。

### Q14：如果 OCR 失败，现场演示怎么办？

答：

> 项目保留了模拟 OCR 按钮作为兜底。真实 OCR 失败时不会清空已有文本，可以点击模拟 OCR 继续验证保存、知识库、详情页和错题复习流程。

### Q15：这个项目和普通记事本有什么区别？

答：

> 普通记事本主要靠手动输入文本。本项目面向学习资料整理，支持图片 OCR、区域识别、原图追溯、知识库检索、错题复习、错误原因和掌握状态管理，更像一个面向学习场景的资料管理系统。

## 8. 现场风险与兜底方案

### 8.1 相册找不到图片

处理方式：

1. 先重开图片选择器。
2. 找 `Pictures/SmartScanTest`。
3. 如果仍找不到，用 adb 重新推送图片。
4. 如果时间紧，直接点击“模拟 OCR”继续演示后续流程。

### 8.2 OCR 识别慢

讲法：

> ML Kit 首次加载模型或处理较大图片时可能需要等待。这里按钮会显示识别中，并暂时禁用，避免重复点击。

### 8.3 OCR 识别不准

处理方式：

1. 切换中文 OCR。
2. 手动修正 OCR 文本。
3. 如果图片太复杂，可以先处理图片后重新选择。
4. 说明数学公式识别是后续优化方向。

### 8.4 App 中已有旧数据

处理方式：

1. 如果数据不影响演示，可以保留，说明是持久化效果。
2. 如果数据太乱，可以在“我的”页面点击“清空本地数据”。
3. 清空前注意确认是否还需要保留演示数据。

## 10. 最终总结话术

可以作为结尾：

> 这个项目目前完成了从图片学习资料到本地知识库的完整闭环：选择图片、中文 OCR、文本编辑、SQLite 保存、知识库检索、详情页原图追溯、错题复习和设置保存。它覆盖了移动应用开发课程要求的 Activity、Fragment、RecyclerView、SQLiteOpenHelper、SharedPreferences、第三方依赖和 Material Design 等核心知识点。
>
> 项目的主要创新点是把 OCR 和学习场景结合起来，并且针对中文教材做了中文 OCR、原图追溯和错题复习管理。对于数学公式识别不完全准确的问题，当前通过可编辑 OCR 文本进行兜底，后续可以继续接入专业公式 OCR、大模型视觉能力或图片裁剪识别。
