## 3. 产品背景

大学生在日常学习中经常需要整理试卷、课堂笔记、PPT 截图、课本内容和错题资料。

传统整理方式通常依赖：

- 相册截图
- 纸质笔记
- 手动输入
- 文件夹分类
- 微信收藏或网盘保存

这些方式存在以下问题：

1. 学习资料分散，后期难以查找。
2. 图片中的文字无法直接检索。
3. 错题整理依赖人工手动摘抄，效率较低。
4. 资料缺乏科目、标签、错题状态等结构化信息。
5. 无法形成长期可复用的个人学习知识库。

因此，本项目拟设计并实现一款移动端学习资料扫描与错题整理 App。系统通过 OCR 识别技术将图片中的文字提取出来，并将识别结果保存到手机本地数据库中，形成个人本地学习资料知识库。用户可以按照科目、标签、关键词和错题状态进行检索、管理和复习，从而提升学习资料整理效率和复习效率。

### 6.4 每日复习提醒

用户开启复习提醒后，系统每天定时提醒用户复习错题。

## 8. 模块定位说明

### 8.1 知识库与错题本的关系

本项目中，**本地知识库**和**错题复习中心**不是两个完全独立的数据源。

二者关系如下：

```text
本地知识库 = 全部学习资料总仓库
错题复习中心 = 本地知识库中 isWrongQuestion = 1 的错题复习视图
```

也就是说，所有资料都存储在 `StudyMaterial` 表中。错题本不单独维护另一套重复数据，而是通过 `isWrongQuestion` 字段筛选出需要复习的资料。

### 8.2 本地知识库定位

本地知识库负责：

- 存资料
- 找资料
- 管理资料
- 按科目、标签、关键词、来源类型检索资料
- 将普通资料标记为错题

本地知识库中的资料可以包括：

- 课堂笔记
- PPT 截图
- 课本内容
- 试卷题目
- 普通例题
- 知识点总结
- 错题资料

### 8.3 错题复习中心定位

错题复习中心负责：

- 复习错题
- 记录错误原因
- 管理错题难度
- 记录复习次数
- 标记掌握状态
- 根据复习状态筛选错题

错题复习中心中的数据来自知识库，但只展示 `isWrongQuestion = 1` 的资料。

### 8.4 二者差异

| 对比项 | 本地知识库 | 错题复习中心 |
|---|---|---|
| 核心定位 | 资料管理中心 | 错题复习中心 |
| 数据范围 | 全部资料 | 被标记为错题的资料 |
| 用户目的 | 查找、分类、管理资料 | 复盘错误、强化薄弱点 |
| 主要筛选 | 科目、标签、关键词、来源类型 | 科目、难度、错因、掌握状态 |
| 核心字段 | title、content、subject、tags、sourceType | wrongReason、difficulty、reviewCount、mastered |
| 主要操作 | 查看、编辑、搜索、标记错题、删除 | 复习一次、已掌握、取消错题、查看详情 |
| 统计指标 | 总资料数、各科资料数 | 错题数、待复习数、已掌握数、复习次数 |

### 9.2 扫描识别模块

#### 功能说明

用户可以通过拍照或选择图片进行 OCR 识别，并将识别结果保存为学习资料。

#### 功能点

1. 支持拍照获取图片。
2. 支持从相册选择图片。
3. 调用 OCR 识别图片文字。
4. 展示图片预览。
5. 展示识别结果。
6. 用户可编辑 OCR 文本。
7. 用户可填写标题。
8. 用户可选择所属科目。

10. 用户可选择是否加入错题本。
11. 用户可填写难度、错误原因和备注。
12. 保存资料到本地数据库。
13. 保存原始图片 Uri 或路径到 `imagePath` 字段。

#### 第一阶段实现

第一阶段先不接入真实 OCR 和相机功能，使用模拟 OCR 文本代替。

点击“模拟 OCR”按钮后，在文本框中自动填入示例内容，例如：

```text
设 A 为三阶矩阵，若 A 与对角矩阵相似，则 A 的特征值为主对角线元素。
本题考察矩阵相似、特征值与对角化条件。
```

#### 第二阶段实现

第二阶段接入：

- 系统相册选择图片
- 图片预览
- Google ML Kit Text Recognition
- 识别结果自动填充到 OCR 文本框
- 图片 Uri 或路径保存到 `imagePath`
- 资料详情页显示原图
- 保留模拟 OCR 作为兜底演示入口

#### 优先级

高。

## 10. 非功能需求

### 10.1 性能需求

1. App 启动速度应较快。
2. 本地资料列表加载流畅。
3. OCR 识别过程应显示加载状态。
4. 数据库查询应避免阻塞主线程。
5. RecyclerView 列表应支持较多数据展示。

### 10.2 可用性需求

1. 页面结构清晰。
2. 按钮和输入框易于理解。
3. OCR 识别结果允许用户手动修改。
4. 数据保存后应有 Toast 提示。
5. 删除资料前应有确认弹窗。
6. 空数据状态需要有友好提示。
7. 权限被拒绝时需要给出提示，不应直接崩溃。

### 10.3 可靠性需求

1. 数据保存后重启 App 不丢失。
2. OCR 识别失败时需要错误提示。
3. 权限被拒绝时需要提示用户手动开启权限。
4. 数据库操作失败时需要提示用户。
5. App 不应出现明显崩溃。
6. 真实 OCR 不可用时，模拟 OCR 仍可作为演示兜底。

### 10.4 安全与隐私需求

1. 用户学习资料默认只保存在本地。
2. 不上传用户图片和文本。
3. 清空数据前必须二次确认。
4. 本地图片路径和文本数据由用户自行管理。
5. 用户可以手动删除全部本地数据。

## 11. 数据结构设计

### 11.1 StudyMaterial 表

用于保存学习资料和错题信息。

| 字段名 | 类型 | 说明 |
|---|---|---|
| id | INTEGER | 主键，自增 |
| title | TEXT | 资料标题 |
| content | TEXT | OCR 识别内容 |
| subject | TEXT | 所属科目 |
| sourceType | TEXT | 来源类型 |
| tags | TEXT | 标签 |
| imagePath | TEXT | 图片路径或 Uri 字符串 |
| isWrongQuestion | INTEGER | 是否错题，0 否，1 是 |
| difficulty | INTEGER | 难度等级，1-5 |
| wrongReason | TEXT | 错误原因 |
| mastered | INTEGER | 是否已掌握，0 未掌握，1 已掌握 |
| nextReviewTime | INTEGER | 下次复习时间，预留字段 |
| note | TEXT | 用户备注 |
| createTime | INTEGER | 创建时间 |
| updateTime | INTEGER | 更新时间 |
| reviewCount | INTEGER | 复习次数 |
| lastReviewTime | INTEGER | 上次复习时间 |

建表 SQL：

```sql
CREATE TABLE study_material (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    title TEXT NOT NULL,
    content TEXT,
    subject TEXT,
    source_type TEXT,
    tags TEXT,
    image_path TEXT,
    is_wrong_question INTEGER DEFAULT 0,
    difficulty INTEGER DEFAULT 1,
    wrong_reason TEXT,
    mastered INTEGER DEFAULT 0,
    next_review_time INTEGER,
    note TEXT,
    create_time INTEGER,
    update_time INTEGER,
    review_count INTEGER DEFAULT 0,
    last_review_time INTEGER
);
```

### 11.2 ReviewRecord 表

用于保存复习记录。

| 字段名 | 类型 | 说明 |
|---|---|---|
| id | INTEGER | 主键，自增 |
| materialId | INTEGER | 对应资料 id |
| reviewTime | INTEGER | 复习时间 |
| result | TEXT | 复习结果 |
| remark | TEXT | 复习备注 |

建表 SQL：

```sql
CREATE TABLE review_record (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    material_id INTEGER NOT NULL,
    review_time INTEGER NOT NULL,
    result TEXT,
    remark TEXT
);
```

### 11.3 TagItem 表，可选

用于保存标签统计。

| 字段名 | 类型 | 说明 |
|---|---|---|
| id | INTEGER | 主键，自增 |
| name | TEXT | 标签名称 |
| count | INTEGER | 使用次数 |

建表 SQL：

```sql
CREATE TABLE tag_item (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL,
    count INTEGER DEFAULT 0
);
```

## 12. 页面流程

### 12.1 新增资料流程

```text
进入扫描页
  ↓
选择图片或模拟 OCR
  ↓
生成识别文本
  ↓
编辑标题、内容、科目、标签、备注
  ↓
选择是否加入错题本
  ↓
保存到本地数据库
  ↓

```

### 12.2 查看资料流程

```text
知识库页面
  ↓
点击资料列表项
  ↓

  ↓

  ↓
```

```text

  ↓
保存到 SharedPreferences
  ↓
注册 WorkManager / Service 任务
  ↓
到点发送通知
```

## 16. Codex 总开发要求

1. 使用 Java + XML。
2. 使用标准 Android Studio 项目结构。
3. 使用 Activity + Fragment。
4. 使用 RecyclerView。
5. 使用 SQLiteOpenHelper。
6. 使用 SharedPreferences。
7. 使用 Material Design 风格。
8. 分阶段开发，不要一次性实现全部功能。
9. 数据库操作封装在 DBHelper 或 Repository 中。
10. 不要把所有业务逻辑都写在 Activity 中。
11. 每个主要类添加中文注释。
12. 每次改动后必须保证项目可以编译运行。
13. 阶段开发时，不要破坏已通过验收的功能。
14. 每次输出修改结果时，需要说明修改了哪些文件、每个文件的作用和测试步骤。
